# Mori 对话设计与提示词实验

更新：2026-11-17。目标是减少用户已指出的“人机感”：同一问题反复得到“闲逛、发呆”，Mori 每轮把话题抛回用户，状态数值主导闲聊，以及把旧意图说成正在发生的事。

## 查到的依据

- [DeepSeek 多轮对话文档](https://api-docs.deepseek.com/guides/multi_round_chat/)明确说 Chat Completions 无服务端会话记忆，调用方须每次带回历史。当前代码只取最近 12 条消息；这能覆盖短对话，但不是长期记忆。
- [DeepSeek 参数文档](https://api-docs.deepseek.com/quick_start/parameter_settings/)给一般对话的建议温度为 1.3，默认 1.0。[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)说明思考模式不采用 temperature。当前应用显式关闭思考模式；所以聊天请求改为 1.3，规则动作 JSON 保持 0.7。温度只调节采样多样性，不能单独修复记忆或人格。
- [EMNLP 2025 多会话人格对话论文](https://aclanthology.org/2025.findings-emnlp.1098.pdf)指出长期人格一致性和回答多样性会互相牵制；其两阶段方法在论文数据上改善了一致性和多样性。这支持未来研究“先回应具体话题，再按相关记忆校准”的方向，不能据此宣称当前 Mori 已达到论文效果。首版不增加每轮第二次付费模型调用。

## 本次改法

1. **角色底座与聊天风格分开。** 底座定义 Mori 的稳定倾向、事实边界和动作权限；聊天规则只在聊天调用中加入，避免污染世界动作 JSON 提议。
2. **先回应具体内容。** 短招呼可以短答；用户认真谈某件事时跟住话题，不像客服总结需求，也不每轮反问。
3. **对重复问题有变化但守事实。** 先看最近聊天；没有新进展就承认，给另一个具体角度；没有真实经历就不编造。旧回答留在历史里供比较。
4. **状态只作背景。** 数值仍能回答相关问题，但提示词明确不主动汇报；旧世界意图不能当作实时行为。页面也把它标作“上次想做”。聊天现在只带入本居民 SQLite 中已审核通过的最近动作；被阻止的动作和其他居民的动作不会成为她的经历。历史里她自己说过的场景仍只是发言，不能反过来充当事件证据。
5. **采样按任务分开。** 日常对话用 DeepSeek 官方推荐的一般对话温度；结构化动作继续较保守的设置。非 DeepSeek 本地兼容模型维持原值，以免改变未经验证的适配。

## 下一轮真实模型评审

用隔离数据库和无私人信息的脚本，与旧版在相同模型、相同输入下比较；每组至少三次，因为采样有波动。场景应包括：连续三次“干嘛呢”；追问“你不是有创作吗”；用户说一件自己的烦心事；提问她不可能知道的现实事实；重启后追问超过最近 12 条的旧事。人工记录每轮是否回应主题、是否复读、是否编造、是否无故反问、是否稳定像 Mori，并记录调用次数和费用。

### 2026-11-17 小样本真实模型迭代

在本机独立端口、临时 SQLite 数据库和空白 Mori 身份上，经页面“发送”调用了 `deepseek-flash` 共 9 次，只发送无私人信息的测试句子；测试库关闭后删除。最初三轮问“干嘛呢”“干嘛呢”“你不是有创作吗”，模型编出窗边、桌边和笔，并把自己编的前一句当成下一句的事实。仅靠禁止编造的通用提示词，下一次仍虚构“整理记下的想法”。加入“当前仅确认正在聊天”的背景后，两轮不再有物理场景，但依旧重复反问。最后将活动问句和重复次数作为当轮提示：三轮样本中，第一次表达刚形成的比喻，第二次给出不同的创作念头且未反问，第三次区分“想到的句子”和实际完成的创作；未再声称没有记录的物理动作。

这是一次定性迭代，**不是**严格的 A/B 测试：不同版本只有一条序列、采样随机，不能据此推断稳定提升或用户喜欢当前诗性表达。精确 token 与费用没有采集。下一轮要让用户试听，并补同输入多次对照、长期记忆与场景边界评审；如果回复显得过长或过度文艺，应调整角色风格，而非继续堆叠禁止词。

已实现第一种保守的长期记忆：只有用户在“她记住的事”里主动保存的文字进入 SQLite；每位居民最多 20 条，每条最多 240 字。用户可查看并删除，删除后后续聊天不再带入该备忘。备忘原文不写入事件日志；网页说明未来聊天会把备忘发送给 DeepSeek。它不自动提取用户事实，不会把模型猜测升级成记忆。后续仍需设计更自然的候选记忆、冲突更正、过期与完整数据擦除；不要把所有历史不加选择地塞进提示词。
